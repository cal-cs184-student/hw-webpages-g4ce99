Overview

In this project, we design a point-mass spring model for realistic physical simulations that we additionally enabled to support custom shaders. We found this project to be very satisfying because of the realism we were able to create with a plane falling over a sphere object. We both agree that the most interesting thing we learned was how to design custom shaders using GLSL and are excited to apply what we learned to our final project!

Varying simulation hyperparameters


With a very low `ks` (1), we see a lot of bending, because the pinned corners aren't "pulling" on the cloth as much. With a high `ks` (100k), we see very little bending, because the pull from the corners is strong enough to just make the cloth flat.

The density corresponds to the weight of the cloth: when the density is very low, we see little bending because the gravitational force isn't very strong.

Increasing damping slows down movement of the cloth by making the velocity update much lower than "normal", while decreasing it makes the cloth oscillate back and forth more times.

Part 3: Handling collisions with other objects

For handling both collisions with spheres and planes, the key first step is to calculate a projection of the point-mass on the object's surface. For the sphere, we do this by shrinking the norm from the point mass's position to the sphere's origin to the radius. For the plane, we use a dot product with the normal to calculate a distance and then use the normal's direction to project the point mass onto the plane. After that, it's just a matter of updating position to be consistent with these corrections. Below are some images created that show off the new properties our simulations can now demonstrate.

In the above images, we can see how varying the spring constant ks changes the resting state of the cloth on the sphere. Specifically, the cloth hugs the sphere more when the ks constant is small and does not wrap around the sphere as much when the constant is large. This makes sense since a larger spring constant means that more force is needed to bend the spring.

Part 4: Handling self-collisions

In order to figure out which point masses are colliding with themselves, we used a spatial hashmap to efficiently find point masses that are close to each other in 3D space. Our hashmap is a subdivided version of the 3D scene with each cell having: width \(w = 3 * cloth\_width / num\_width\_points\), height \(h = 3 * cloth\_height / num\_height\_points\), depth \( t = max(w, h)\).

Given a 3D position of a point mass, we use the following function to find its key in the hashmap:
\[((pos.x - fmod(pos.x, w)) / w) + b * ((pos.y - fmod(pos.y, h)) / h) + b * b * ((pos.z - fmod(pos.z, t)) / t)\] where b is equal to the max of the cloth width and height.

At every simulation step, we build the spatial hashmap and iterate through each point mass, adjusting its position based on itself self-collisions with all of the other points in with the same key in the hashmap. To determine if two point masses self-collide, we check to see if the distance between the two is less than 2 times the cloth thickness, and if they do, we store a correction vector moving the current point mass exactly 2 times the cloth thickness away from the second point mass. At the end of the self-collision adjustment, we update the point mass's position to be its last position + the average correction vector / simulation_steps. We include this additional division by simulation steps to ensure stability of updates. The effectiveness of this implementation can be seen in the screenshots of simulations involving self-collision that are shown below.

Part 5: Shaders

A shader program is code that tells a GPU how to color a scene. It does this with two key components: vertex shaders and fragment shaders. The vertex shaders are in charge of setting vertex-level information that a shading model can use to determine the color of a vertex (normals, positions, colors). The fragment shaders work after rasterization and use vertex-level information along with a specific material shading model to generate the coloring/lighting effects on a specific pixel containing this vertex. The Blinn-Phong shader calculates lighting through three components (these can be seen individually/combined in the images below):
  • Ambient lighting applies a minimum light level (0.1 × material color) to all surfaces.
  • Diffuse lighting simulates light scatter on surfaces using the dot product between surface normal and light direction (n_l). Light intensity decreases with distance using the inverse square law. The shader uses max(0, n_l) to ensure only surfaces facing the light are illuminated.
  • Specular lighting creates highlights using a half-vector (h) - the normalized sum of view and light directions. The dot product between surface normal and half-vector (n_h) determines highlight intensity. The power function (^30) controls highlight size. The 0.5 coefficient scales the highlight brightness.

We also explored using custom texture mapping from image data. An example of our favorite Cal texture mapped onto the simulation can be seen below:
Bump mapping creates the illusion of texture through lighting tricks without altering the actual geometry, resulting in a cloth with visible surface detail but perfectly smooth silhouettes. Displacement mapping physically modifies the mesh, producing genuine geometric detail with pronounced wrinkles and folds.

At low mesh resolution (-o 16 -a 16), the bump-mapped cloth shows artificial texture on a slightly polygonal surface with angular edges, while the displaced version exhibits chunkiness. At higher resolution (-o 128 -a 128), bump mapping displays refined surface lighting with smoother but still geometrically unaltered silhouettes, whereas displacement mapping generates realistic cloth with detailed geometric wrinkles, creating more realistic shadow patterns.
